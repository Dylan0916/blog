# i18n (zh-TW default + English mirror) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a fully browsable English mirror of the blog with translated UI chrome and per-post English bodies that fall back to Chinese when no translation exists.

**Architecture:** Enable Astro i18n (`zh-TW` default unprefixed, `en` under `/en`). A bilingual UI string table drives all chrome via `useTranslations(locale)`. Shared layouts/components take a `locale` prop. A parallel `src/pages/en/` route tree renders English chrome; post bodies resolve to the `.en.md` twin or fall back to the Chinese post. Posts are paired by a `translationKey` frontmatter field.

**Tech Stack:** Astro 6.4, TypeScript, Tailwind v4, bun. No test runner — verification is `bun run build` clean + browser checks.

**Verification convention:** every task ends with `bun run build` (expect `✔ No issues`, 0 errors). Browser checks run against `bun run dev` (http://localhost:4321).

```ts
import type { CollectionEntry } from "astro:content";
import slugify from "@/utils/slugify";
import { DEFAULT_LOCALE, type Locale } from "@/i18n/ui";

type Post = CollectionEntry<"posts">;

/** Posts authored in the default (zh-TW) locale, drafts dropped. */
export const getDefaultLocalePosts = (posts: Post[]) =>
  posts.filter(p => !p.data.draft && (p.data.lang ?? DEFAULT_LOCALE) === DEFAULT_LOCALE);

/** The English twin of a post, matched by translationKey. */
export const findEnglishTwin = (posts: Post[], key: string | undefined) =>
  key ? posts.find(p => p.data.lang === "en" && p.data.translationKey === key) ?? null : null;

/**
 * For an English page request keyed by the default-locale slug, return the
 * post whose body should render: the English twin if it exists, else the
 * default-locale post (fallback).
 */
export const resolveEnglishBody = (defaultPost: Post, posts: Post[]): Post =>
  findEnglishTwin(posts, defaultPost.data.translationKey) ?? defaultPost;

/** URL of a post in a target locale (English mirror lives under /en). */
export const localizedPostUrl = (post: Post, locale: Locale) => {
  const base = `/posts/${slugify(post.data)}/`;
  return locale === "en" ? `/en${base}` : base;
};
```

Note: English twins reuse the Chinese post's slug (same `postSlug`/`translationKey` route key) so `/en/posts/<slug>` mirrors `/posts/<slug>`. The English `.en.md` MUST set `postSlug` equal to its Chinese twin.

- [ ] **Step 4: filter getSortedPosts to default locale**

Replace the body of `src/utils/getSortedPosts.ts`:

```ts
import type { CollectionEntry } from "astro:content";
import { DEFAULT_LOCALE } from "@/i18n/ui";

const getSortedPosts = (posts: CollectionEntry<"posts">[]) =>
  posts
    .filter(
      ({ data }) => !data.draft && (data.lang ?? DEFAULT_LOCALE) === DEFAULT_LOCALE
    )
    .sort(
      (a, b) =>
        Math.floor(new Date(b.data.pubDatetime).getTime() / 1000) -
        Math.floor(new Date(a.data.pubDatetime).getTime() / 1000)
    );

export default getSortedPosts;
```

This keeps the Chinese listings (home/tags/RSS/search/posts index) free of `.en` variants automatically — they all run through `getSortedPosts`.

### Task 9: /en post detail with fallback

**Files:**
- Create: `src/pages/en/posts/[slug]/index.astro`

- [ ] **Step 1: route**

```astro
---
import { getCollection } from "astro:content";
import PostLayout from "@/layouts/PostLayout.astro";
import getSortedPosts from "@/utils/getSortedPosts";
import { resolveEnglishBody, localizedPostUrl } from "@/utils/postLocale";
import slugify from "@/utils/slugify";
import type { AdjacentPost } from "@/types";

export async function getStaticPaths() {
  const all = await getCollection("posts");
  const sorted = getSortedPosts(all); // default-locale, newest first

  const toNav = (p, locale): AdjacentPost =>
    p ? { title: p.data.title, url: localizedPostUrl(p, locale) } : null;

  return sorted.map((post, i) => ({
    params: { slug: slugify(post.data) },
    props: {
      post: resolveEnglishBody(post, all),
      prevPost: toNav(sorted[i + 1], "en"),
      nextPost: toNav(sorted[i - 1], "en"),
      counterpartUrl: localizedPostUrl(post, "zh-TW"),
    },
  }));
}

const { post, prevPost, nextPost, counterpartUrl } = Astro.props;
---

<PostLayout
  post={post}
  prevPost={prevPost}
  nextPost={nextPost}
  locale="en"
  counterpartUrl={counterpartUrl}
/>
```

## Notes / gotchas

- `getSortedPosts` is the single choke point that keeps `.en` posts out of Chinese listings — don't bypass it in listing pages.
- English twins MUST share `postSlug` with their Chinese source, else `/en/posts/<slug>` won't line up with `/posts/<slug>` and the toggle/hreflang break.
- The `/en` listing pages intentionally show the same (Chinese-authored) post set with English chrome; bodies only differ on pages that have an `.en.md`.
- Astro i18n with `prefixDefaultLocale: false` means root stays unprefixed; do NOT add a `/zh-TW` tree.
- Search `/en/search` reuses the Fuse index built from authored titles/descriptions (Chinese for untranslated posts) — chrome only is English. Documented limitation.
