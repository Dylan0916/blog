# i18n (zh-TW default + English mirror) — Design

Date: 2026-05-28
Status: approved-pending-spec-review

## Goal

Add a browsable English version of the blog alongside the existing
Traditional Chinese site. The UI chrome is fully translated; article
bodies are translated per-post and fall back to Chinese when no English
version exists.

## Decisions (locked)

- **Routing**: Astro i18n. `locales: ["zh-TW", "en"]`, `defaultLocale:
  "zh-TW"`, `routing: { prefixDefaultLocale: false }`. Chinese stays at
  root (`/posts/x`), English under `/en/` (`/en/posts/x`).
- **Mirror**: English side is fully browsable — `/en`, `/en/posts`,
  `/en/posts/<slug>`, `/en/tags`, `/en/tags/<tag>`, `/en/about`,
  `/en/search`.
- **Content fallback**: every post appears in both locales' listings.
  An English post page renders the English body if a `.en.md` twin
  exists, otherwise it renders the Chinese body (chrome stays English).
- **UI strings**: a bilingual table (`zh-TW` / `en`) drives all chrome —
  nav, footer, section headings, buttons (Go back / Back to Top),
  adjacent-post labels, tag labels, dates.
- **Tags**: tag strings are NOT translated (raw values like `面試心得`
  shown as-is in both locales). Only the surrounding UI labels (`Tag:`,
  `Tags`, "All the articles with the tag …") are translated.
- **about**: same fallback rule — English `about.en.md` if present, else
  the Chinese `about.md` body.
- **Language switcher**: present site-wide, toggles between the current
  page and its counterpart locale (EN ⇄ 中).
- **Post file naming**: English twin is `<name>.en.md` next to the
  Chinese `<name>.md` in `src/content/posts/`.
- **Pairing**: a `translationKey` frontmatter field links the two
  language variants; `lang` marks the language (`"zh-TW"` default,
  `"en"` on `.en.md`).

## Schema changes (`src/content.config.ts`)

Add to the post schema:

```ts
lang: z.enum(["zh-TW", "en"]).default("zh-TW"),
translationKey: z.string().optional(),
```

`translationKey` is shared by a post and its translation (e.g.
`nodejs-26-intro`). The switcher and fallback resolver match on it.

## Components / units

- `src/i18n/ui.ts` — the string table `{ "zh-TW": {...}, en: {...} }`
  plus `useTranslations(locale)` returning a typed `t` lookup. One flat
  key namespace (`nav.posts`, `post.goBack`, `tag.label`, …). English
  falls back to a key's zh-TW value if missing (shouldn't happen; guard
  anyway).
- `src/utils/getLocale.ts` — small helper to resolve the active locale
  from `Astro.currentLocale` with the default applied.
- `src/utils/posts.ts` (or extend existing utils):
  - `getDefaultLocalePosts()` — non-draft posts in the default locale
    (drop `.en` variants) for the Chinese listings.
  - `resolvePostForLocale(translationKey, locale)` — returns the English
    twin if it exists, else the default-locale post (fallback).
  - `getTranslationCounterpartUrl(post, targetLocale)` — for the
    switcher.
- `Datetime` — accept a `locale` prop; format via
  `toLocaleDateString(locale)`.
- `Header`, `Footer`, `Breadcrumbs`, `AdjacentPostNav`, `Card`,
  `Posts`, search UI — accept/read the active locale and pull strings
  from `useTranslations`.
- `LanguageToggle.astro` — renders the EN ⇄ 中 link, hidden if no
  counterpart route exists (about/tags always have a counterpart; posts
  always do via fallback, so it's effectively always shown).

## Routing layout

Keep the existing root (zh-TW) pages as-is but make them locale-aware
(pass `locale="zh-TW"`). Add a parallel `src/pages/en/` tree whose pages
are thin wrappers that pass `locale="en"`. Shared page bodies move into
layouts/components that take a `locale` prop so logic isn't duplicated.

```
src/pages/
  index.astro                 (zh-TW home)
  posts/index.astro           (zh-TW posts list)
  posts/[slug]/index.astro    (zh-TW post + fallback already n/a)
  tags/index.astro
  tags/[tag].astro
  search.astro
  en/
    index.astro               (en home)
    posts/index.astro
    posts/[slug]/index.astro   (en body or zh fallback)
    tags/index.astro
    tags/[tag].astro
    search.astro
    about.astro
```

`about` becomes `src/pages/en/about.astro` rendering `about.en.md` if
present else the zh `about.md` body.

## Out of scope (YAGNI)

- **English RSS** — keep the single zh `/rss.xml`. (Note in README.)
- **Per-post OG image for English** — English post pages use the site
  default OG image; do NOT add an `/en` dynamic OG route (satori/resvg
  generation is heavy and the English audience is secondary).
- **Translating tag values** — locked out above.
- **Localized 404** — single existing 404 stays.
- **Search index per locale** — `/en/search` reuses the existing Fuse
  index (titles/descriptions as authored, i.e. Chinese for untranslated
  posts); only the search UI chrome is English.

## SEO

- Each page emits `<link rel="alternate" hreflang>` pairs (zh-TW ⇄ en)
  for its counterpart.
- `lang` attribute on `<html>` reflects the active locale.
- Sitemap: `@astrojs/sitemap` already enabled; with Astro i18n config it
  picks up both locale trees.

## Deliverable: Node.js 26 English post

- Create `src/content/posts/2026-05-27_nodejs-26-intro.en.md` with
  `lang: en`, `translationKey: nodejs-26-intro`, `draft: false`, English
  translation of the body.
- Add `translationKey: nodejs-26-intro` to the existing Chinese post.

## Verification

- `bun run build` clean.
- Browser: `/` (zh chrome), `/en` (en chrome), `/en/posts/<node-slug>`
  (English body), `/en/posts/<some-other-slug>` (Chinese body + English
  chrome = fallback), language switcher both directions, `/en/tags`
  (English labels, raw tag strings), mobile.
